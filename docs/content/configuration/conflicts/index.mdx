---
title: Conflicts
description: Field-by-field explanation of Identica's conflict resolution configuration area.
---

The conflicts configuration controls how Identica resolves provider conflicts such as username collisions.
Use this file when you want to change the default resolver chain for a conflict key or define provider-pair-specific conflict behavior.

### conflicts

- Takes: a map keyed by conflict key
- Affects: how Identica resolves registered conflicts before allowing or denying progress

The current built-in conflict key is `username`.

<Tabs items={["YAML", "JSON"]}>
  <Tab value="YAML">
```yaml
conflicts:
  username:
    default:
      resolvers:
        - id: "format_display"
          parameters:
            format:
              pattern: "{username}*"
            target: "joiner"
    pairs:
      - providers:
          - "premium"
          - "credential"
        resolvers:
          - id: "format_display"
            parameters:
              format:
                pattern: "{username}_{incomingProvider}"
              target: "joiner"
```
  </Tab>

#### conflicts.<key>.default

- Takes: a conflict rule object
- Affects: the fallback resolver chain for that conflict key

The `default` rule runs when no provider-pair rule produces a non-pass result.

#### conflicts.<key>.pairs

- Takes: a list of conflict rule objects
- Current default: `[]`
- Affects: provider-pair-specific conflict resolution before the default rule runs

Each pair rule is matched when both provider ids are present in the conflict context, regardless of their order in the list.

#### conflicts.<key>.pairs[].providers

- Takes: a list of provider ids
- Affects: which provider combination the pair rule applies to

Most rules should contain exactly two provider ids such as `premium` and `credential`.

#### conflicts.<key>.default.force
#### conflicts.<key>.pairs[].force

<Badge type="warning">Advanced</Badge>

- Takes: `true` or `false`
- Current default: `false`
- Affects: whether Identica should run a resolver even when it does not declare support for the conflict key

Leave this disabled unless you intentionally want to override normal resolver compatibility checks.

#### conflicts.<key>.default.resolvers
#### conflicts.<key>.pairs[].resolvers

- Takes: a list of resolver entries
- Affects: the ordered resolver chain for the selected rule

Resolvers run in list order.
If a resolver returns `PASS`, Identica continues to the next resolver.
If every resolver passes, Identica falls back to the default rule, and if the default rule still passes, Identica logs a warning and allows the conflict.

#### conflicts.<key>.default.resolvers[].id
#### conflicts.<key>.pairs[].resolvers[].id

- Takes: a string
- Affects: which registered conflict resolver is invoked

Resolver ids must match a resolver registered by Identica core or an installed provider.

#### conflicts.<key>.default.resolvers[].parameters
#### conflicts.<key>.pairs[].resolvers[].parameters

- Takes: an object
- Current default: `{}`
- Affects: resolver-specific behavior

Parameter structure depends on the selected resolver.
For example, the built-in `format_display` resolver expects a `format.pattern` value and a `target`.
