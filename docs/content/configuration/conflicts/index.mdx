title: Conflicts
description: Field-by-field explanation of Identica's conflict resolution configuration area.

The conflicts configuration controls how Identica resolves provider conflicts such as username collisions.

Conflicts are configured per conflict key.
Each key defines:

- a `default` rule
- optional provider-pair-specific `pairs` rules
- an ordered list of resolvers inside each rule

## conflicts

- Takes: a map keyed by conflict key
- Affects: how Identica resolves registered conflicts before allowing or denying progress

Use this section when you want to change the resolver chain for a conflict type or define provider-specific behavior for a provider combination.

<Tabs items={["YAML", "JSON"]}>
  <Tab value="YAML">
```yaml
conflicts:
  username:
    default:
      resolvers:
        - id: "format_display"
          parameters:
            format:
              pattern: "{username}*"
            target: "joiner"
    pairs:
      - providers:
          - "premium"
          - "credential"
        resolvers:
          - id: "format_display"
            parameters:
              format:
                pattern: "{username}_{incomingProvider:8}"
              target: "joiner"
```
  </Tab>
  <Tab value="JSON">

## Rule selection

When Identica resolves a conflict for a key such as `username`, it evaluates rules in this order:

1. matching provider-pair rules from `pairs`
2. the `default` rule

Inside a rule, resolvers run in list order.
If a resolver returns `PASS`, Identica continues to the next resolver.
If every resolver passes, Identica falls back to the next applicable rule.
If no rule produces a result, Identica logs a warning and allows the conflict.

## conflicts.<key>.default

- Takes: a conflict rule object
- Affects: the fallback resolver chain for that conflict key

The `default` rule runs when no provider-pair rule produces a non-pass result.

## conflicts.<key>.pairs

- Takes: a list of conflict rule objects
- Current default: `[]`
- Affects: provider-pair-specific conflict resolution before the default rule runs

Each pair rule is matched when both provider ids are present in the conflict context, regardless of their order in the list.

## conflicts.<key>.pairs[].providers

- Takes: a list of provider ids
- Affects: which provider combination the pair rule applies to

Most pair rules should contain exactly two provider ids such as `premium` and `credential`.

## conflicts.<key>.default.force
## conflicts.<key>.pairs[].force

<Badge type="warning">Advanced</Badge>

- Takes: `true` or `false`
- Current default: `false`
- Affects: whether Identica should run a resolver even when it does not declare support for the conflict key

Leave this disabled unless you intentionally want to bypass normal resolver compatibility checks.

## conflicts.<key>.default.resolvers
## conflicts.<key>.pairs[].resolvers

- Takes: a list of resolver entries
- Affects: the ordered resolver chain for the selected rule

Each resolver entry selects a resolver type and provides its configuration parameters.

## conflicts.<key>.default.resolvers[].id
## conflicts.<key>.pairs[].resolvers[].id

- Takes: a string
- Affects: which registered conflict resolver is invoked

Resolver ids must match a resolver registered by Identica core or an installed provider.

## conflicts.<key>.default.resolvers[].parameters
## conflicts.<key>.pairs[].resolvers[].parameters

- Takes: an object
- Current default: `{}`
- Affects: resolver-specific behavior

The parameter structure depends on the selected resolver type.

## Resolver types

The sections above describe how conflict rules select and run resolvers.
The sections below describe the built-in resolver types themselves.

### format_display

`format_display` formats a replacement value from the current conflict context and returns that formatted value as the resolver result.

#### conflicts.<key>.default.resolvers[].parameters.format.pattern
#### conflicts.<key>.pairs[].resolvers[].parameters.format.pattern

- Takes: a string
- Affects: the formatted override value produced by `format_display`

Supported placeholders:

- `{username}` or `{requested}`
- `{incomingProvider}` and `{existingProvider}`
- `{incomingProviderId}` and `{existingProviderId}`
- `{random}` or `{random:4}`

Provider display-name placeholders support optional truncation with `:maxSymbolCount`.

Examples:

```text
{incomingProvider}
{incomingProvider:8}
{existingProvider:6}
{username}_{incomingProvider:8}_{random:3}
```

Only `{incomingProvider}` and `{existingProvider}` support truncation.

#### conflicts.<key>.default.resolvers[].parameters.format.uppercase
#### conflicts.<key>.pairs[].resolvers[].parameters.format.uppercase

- Takes: `true` or `false`
- Current default: `false`
- Affects: whether the full formatted result is converted to uppercase

#### conflicts.<key>.default.resolvers[].parameters.format.lowercase
#### conflicts.<key>.pairs[].resolvers[].parameters.format.lowercase

- Takes: `true` or `false`
- Current default: `false`
- Affects: whether the full formatted result is converted to lowercase

Avoid enabling both `uppercase` and `lowercase` at the same time.

#### conflicts.<key>.default.resolvers[].parameters.target
#### conflicts.<key>.pairs[].resolvers[].parameters.target

- Takes: `"joiner"`, `"existing"`, or `"both"`
- Current default: `"joiner"`
- Affects: which side receives the formatted override value
