---
title: Providers
description: Field-by-field explanation of Identica's provider configuration area.
---

The providers configuration controls which identity providers are enabled and how provider-specific behavior is applied.
Use this file to enable providers, set priority and entrypoints, configure verification, and apply provider-specific overrides.

### providers

- Takes: a list of provider entries
- Affects: provider enablement, ordering, entrypoint routing, verification policy, and provider-specific session overrides

Provider ids should match installed provider descriptors, such as `premium` or `credential`.

<Tabs items={["YAML", "JSON"]}>
  <Tab value="YAML">
```yaml
providers:
  - id: "premium"
    displayName: "PR"
    enabled: true
    priority: 100
    overrides:
      sessionConcurrencyPolicy: "REJECT_NEW"
      recognition:
        enabled: true
        signals:
          - "USERNAME"
          - "VIRTUAL_HOST"
        eligibility:
          allowOnUntrustedIp: false
```
  </Tab>
  <Tab value="JSON">
```json
{
  "providers": [
    {
      "id": "premium",
      "displayName": "PR",
      "enabled": true,
      "priority": 100,
      "overrides": {
        "sessionConcurrencyPolicy": "REJECT_NEW",
        "recognition": {
          "enabled": true,
          "signals": ["USERNAME", "VIRTUAL_HOST"],
          "eligibility": {
            "allowOnUntrustedIp": false
          }
        }
      }
    }
  ]
}
```
  </Tab>
</Tabs>

#### overrides

- Takes: an object
- Current default: `{}` for providers without overrides
- Affects: provider-specific behavior that differs from global defaults

The `overrides` object is kept in generated config as a stable place for provider-specific exceptions.
Configura keeps the object structure without filling every possible child field.

#### overrides.sessionConcurrencyPolicy

<Badge type="warning">Advanced</Badge>

- Takes: `"ALLOW_MULTIPLE"`, `"REPLACE_EXISTING"`, or `"REJECT_NEW"`
- Current default: absent
- Affects: how live-session replacement behaves for this specific provider

If this is absent, Identica uses `settings.connection.sessions.concurrencyPolicy`.

#### overrides.recognition.enabled

<Badge type="warning">Warning</Badge>

- Takes: `true` or `false`
- Current default: absent
- Affects: whether this provider inherits or overrides `settings.connection.sessions.recognition.enabled`

When this field is absent, the provider inherits `settings.connection.sessions.recognition.enabled`.
Use it when one provider should allow reconnect recognition while another should require full provider authentication every time.

#### overrides.recognition.signals

<Badge type="warning">Warning</Badge>

- Takes: a list containing any of `"USERNAME"`, `"IP"`, `"VIRTUAL_HOST"`
- Current default: absent
- Affects: the signal set used when this provider evaluates reconnect recognition

When this field is absent or empty, the provider inherits `settings.connection.sessions.recognition.defaultSignals`.

#### overrides.recognition.eligibility.allowOnUntrustedIp

<Badge type="warning">Advanced</Badge>

- Takes: `true` or `false`
- Current default: `false`
- Affects: whether this provider stays recognition-eligible from client IPs blocked by `settings.connection.sessions.recognition.eligibility.untrustedIps`

Leave this `false` for the normal safety posture.
Set it to `true` only when this specific provider should remain recognition-eligible on client IPs that are otherwise blocked.

Recognition is intentionally disabled by default because signal matching can be unsafe in shared-network environments.
IP-based matching in particular can be exploited behind NAT, carrier-grade NAT, shared Wi-Fi, VPN exits, hosting proxies, or other setups where several different players appear to come from the same address.

Enable recognition only if you understand that tradeoff and accept the risk for your environment.

#### joinRestriction.enabled

<Badge type="warning">Advanced</Badge>

- Takes: `true` or `false`
- Current default: `false`
- Affects: whether this provider exposes a runtime-toggleable join restriction policy

When this is `false`, `/identica admin provider restriction enable <provider>` will fail for that provider.
When this is `true`, the configured `mode` can be activated at runtime by command.

#### joinRestriction.allow

<Badge type="warning">Advanced</Badge>

- Takes: a list containing `"RECOGNIZED"` and/or `"LINKED"`
- Current default: absent unless explicitly configured
- Affects: what the runtime provider restriction does when it is active

Available conditions:

- `RECOGNIZED`: only reconnect-recognized players may continue through this provider
- `LINKED`: already-linked players may continue through this provider

When the list contains both values, players may continue when either condition matches.
When the list is empty, all new joins through the provider are denied.
