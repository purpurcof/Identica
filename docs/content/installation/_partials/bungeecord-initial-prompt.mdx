    Velocity usually does not need extra initial prompt resend handling for this installation flow.
  </ContentTab>
  <ContentTab value="BungeeCord">
    Keep `connection.initialPrompt.resendUntilInteraction` enabled on BungeeCord.

    Because of BungeeCord's platform limitations, Identica cannot reliably determine one final "the player is fully connected and will definitely see the first prompt now" moment for every flow.
    To handle that safely, Identica can queue the initial waiting prompt and resend it after the first step routing until the player interacts or the pending state changes.

    A practical baseline looks like this:

    ```yaml
    connection:
      initialPrompt:
        resendUntilInteraction: true
        resendInterval: 1500ms
    ```

    If you disable this on BungeeCord, a player can miss the first interactive prompt after routing and end up confused because the flow is waiting for input they never saw.
  </ContentTab>
